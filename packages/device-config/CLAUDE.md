# @restos/device-config

**Owning specs: `specs/00-platform-overview.md §7` (the config layers) for the shape; `specs/03-service-flow.md` for aging, `specs/01-kernel.md` for identity, `specs/27-visual-language.md` for panel density — read the one you are touching (AGENTS.md routing).**

- The `00 §7` configuration a **device host** resolves at boot: `resolveAging` (`03-F14`/`03-F47` thresholds, layer 2), `resolveServeSignal` (`03-F52` serve-signal ownership, layer 2), `resolveDeviceIdentity` (`01-F2`/`01-F13`, layer 3) and `resolvePanelDensity` (`27-F68`, layer 3). Each is a pure `resolveX` plus a `describeX` that says on the boot line **which source answered** — `00 §5.7` bites hardest here, because every one of these is wrong in a way that looks exactly like being right.
- **Why a package: `18 §2` + `DEC-ARCH-001`.** Each had a second consumer, and `18 §2` makes *"Apps NEVER import ... other apps"* a MUST. `aging.ts` was `apps/pass-kds`'s and the counter reached across for it; the other two were `apps/pos-electron`'s and the pass reached across — which made the two apps a **cycle**. `DEC-ARCH-001` rules EXTRACT at the moment the second consumer appears, and rules against a copy for `03-F40`'s reason: a second local helper is a second interpretation, and the two diverge silently. **`serve-signal.ts` was born here rather than moved here** (August 2026): `03-F52` makes the pass screen's handover control and `02-F31`'s settlement auto-advance read the SAME assignment, so it had two consumers before it had one line — and the FR names the failure a copy would produce, with a price attached (*"Two surfaces each carrying their own default is how a pass screen and a till come to disagree about who owns handover with every gate green — the failure `01-F60`'s enabled-set drift already cost this product once"*). It is also the first module here that imports `@restos/domain` (a TYPE-only edge, for `DeviceClass` on the roster input); `packages → packages` is an ordinary edge and the inversion below is unchanged.
- **`03-F14` is ONE org policy and this is its only declaration.** `05-F1` alarms the manager off *"the red aging threshold (03-F14)"*, so a counter reading neutral while the pass reads red is three surfaces disagreeing about whether the food is late. Do not add a second threshold table anywhere, including a "just a default" literal in a component.
- **Three pinned readings live here, not in the FRs, and must not be re-decided silently.** (a) `03-F14` states defaults for dine-in and delivery only; **takeaway, pickup and an unknown/absent order type take dine-in's 10/20** (argued in `aging.ts`'s header). (b) A malformed threshold string is **REFUSED WHOLE and NOT APPLIED** — the shipped defaults stay in force and the reason is reported (`01-F17`, commandment 4: a typo must never take a surface down mid-service). (c) `03-F52` requires the surface to REPORT an assumed serve-signal owner and does not say which owner is assumed; **`settlement` is assumed**, argued in `serve-signal.ts`'s header — it keeps `02-F31` byte-identical on every branch that has configured nothing, where assuming `pass` would stop every existing till auto-serving and leave a branch with no pass screen with no producer for `served` at all. A `waiter`-only roster derives `settlement` for the same reason, and that line moves the day `apps/waiter` ships.
- **`dev-staff.ts` is a DEV SEED and not configuration, and it is here for the same `DEC-ARCH-001` reason** (August 2026, `03-F53`). `DEV_STAFF`/`seedDevStaff` were declared in `apps/pos-electron/src/main/index.ts` until the pass screen got `01-F26`'s PIN session and the roster acquired its second consumer; `03-F53`'s OWED (3) requires *"one declaration read by both apps … never a second copy"*, because two rosters is a till and a pass screen that disagree about who is on shift in a ledger `01-F1` cannot correct. **The PIN is not in the file** — and ⚠ **this bullet described a RETIRED credential shape until 2026-08-17**: it said *"`DEV_PIN_ENV` (`RESTOS_DEV_PIN`) carries it"*, **one key for the whole roster**, which is exactly the authorization hole closed in August 2026 (one `hashPin` result written onto every member, the branch manager's row included, so `02-F22`'s guard was one tile-tap from the digits both cashiers type all shift). A session routed by that sentence configures one variable, gets ONE CASHIER, and believes it has a roster. The live contract is **`DEV_STAFF_PIN_ENV`: one key per member, pairwise distinct, NO fallback between members** (`RESTOS_DEV_PIN` survives as the first cashier's key and nobody else's), and a member nobody configured is **absent from the grid** — the honest state of a device no roster has reached (`00 §5.7`), and what production looks like until the staff transport lands (`01-F47` admits *devices, not people*). The registry argument is **structurally typed**, exactly as `DisplayFacts` is, so this package still depends on `@restos/domain` alone. ⚠ **The sentence *"`version() + 1` and never a literal"* was also here, and it too is superseded (2026-08-17, R21/`01-F56`).** It was right that `staff.ts` refuses an OLDER snapshot as `stale`, so a hardcoded `version: 1` would leave a device that ran once with a roster and every launch after without one — and wrong that incrementing cures it, because that makes the version a dev till holds *the number of times it has been switched on*, a quantity no publisher can know, so a real first snapshot at v1 is refused `stale` on any till booted twice. The seed **stands down entirely when the device holds a member `DEV_STAFF` does not name** — R28 draws the line at RECEIVED vs NEVER-RECEIVED and *not* at a version number, so the `version() > 0` guard `apps/pos-electron/src/main/catalog.ts:241` ships for the MENU is refused here: a roster published at v0 has been received, and that guard cannot see it. ⚠ **A fixed `version: 0` was the first answer and it stood for one day; the live answer is the HELD version** (`seedVersionFor`, corrected 2026-08-17 after a review measured it). A snapshot AT the held version is `staff.ts`'s self-heal either way — but a literal `0` is only *at* the held version on a device holding `0`, and **every device the previous build ever ran holds `>= 1`** because that build applied at `version() + 1`. On those, a `0` snapshot was refused `stale` on every launch, for ever and silently: a changed `RESTOS_DEV_PIN_*` never took effect again, and a till whose last old-build boot was the **pre-August shared-PIN** build kept one credential across all three rows unrepairably — the exact authorization hole this bullet says was closed, with `02-F22`'s guard one tile-tap from the cashiers' digits. What the held version does NOT repair is named in `seedVersionFor`: an old-build till holds an inflated version of fiction, and a real publisher's v1 is still refused `stale` on it (wipe `device.db`). **The boot line reports the DEVICE, not the request.** `describeDevStaff(env, device?)` takes `{ registry, identity, seeded }` — all three REQUIRED inside the optional bag, on `01-F60`'s "a caller who forgot the argument silently received no check" precedent — because the environment says what an operator ASKED for and that is a different fact from what is on the device (`00 §5.7`). ⚠ *It took the registry alone for one day, consulted only through the received-members test, so in every state with no received member it fell back to the environment — including states where the write had been REFUSED: a publisher that empties a roster with a delta leaves `version 2, members 0`, and the line said `staff: 3 seeded … One Argon2id credential each` over a device nobody can sign in to.* `identity` is there because `01-F26` makes a role a per-(user, **location**) assignment: `02-F22`'s day-open clause is now decided by `@restos/domain`'s `can()` and not by a role set copied into this package, which had dropped the branch filter and so stayed silent for a delivered manager assigned to **another** branch. **Delete the module when the transport lands.**
- **`packages → apps` is the inversion to watch.** Nothing here may import from `apps/` or `services/`; that compiles, links and runs while inverting `18 §2` outright (`DEC-ARCH-001` records the same trap). These modules take an env record, a raw string and a `run` callback as arguments precisely so they need no host.
- **The RESOLVERS have no suite here, by design; `dev-staff.ts` now does.** ⚠ This line read *"No suite lives here, by design"* until 2026-08-17 and the second half of it is still exactly right: `resolveAging`, `resolveServeSignal`, `resolveDeviceIdentity` and `resolvePanelDensity` are owned by the consumers' suites — `apps/pos-electron`'s `panel-density.test.ts`, `device-identity-seam.test.ts` and `orders-aging.test.ts`, and `apps/pass-kds`'s `pass-queue.test.ts`, `ready-mark.test.ts`, `__acceptance__/handover.test.ts` (§A owns the whole of `resolveServeSignal`) and `__acceptance__/shared-config-extraction.test.ts`. `DEC-ARCH-001` was a pure move and duplicated none of them. What changed is that `src/__acceptance__/dev-staff-seed.test.ts` landed (`24 §3` step 2, authored from spec text by a session that wrote no implementation): the seed is not a resolver — it WRITES to a credential registry, and the property it is asserted on is what happens when the registry already holds a roster a real transport delivered (R21, `01-F21`/`01-F61`/`01-F56` — ⚠ this cited `01-F52` until 2026-08-17, and the suite's own header records why that is wrong: `01-F52` is the CATALOG's FR and its named consequence is that *"catalog is **org-scoped**"*, while the roster is branch-scoped. The property was right and the ID carrying it was not, which is the citation half of commandment 2). No consumer suite can own that, because it is not about either host. `package.json`'s `test` is `vitest run` and its `//devDependencies` note explains why `@restos/sync-client` is a **test-only** edge: the suite asserts against the production `createStaffRegistry` rather than a hand-copy of its `clearAll`-on-snapshot and `stale` semantics. The SHIPPING dependency is still `@restos/domain` alone — `DevStaffRegistry` is structurally typed precisely so no runtime edge exists — and nothing here may import from `apps/` or `services/` either way.
