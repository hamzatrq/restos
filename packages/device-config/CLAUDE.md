# @restos/device-config

**Owning specs: `specs/00-platform-overview.md §7` (the config layers) for the shape; `specs/03-service-flow.md` for aging, `specs/01-kernel.md` for identity, `specs/27-visual-language.md` for panel density — read the one you are touching (AGENTS.md routing).**

- The `00 §7` configuration a **device host** resolves at boot: `resolveAging` (`03-F14`/`03-F47` thresholds, layer 2), `resolveDeviceIdentity` (`01-F2`/`01-F13`, layer 3) and `resolvePanelDensity` (`27-F68`, layer 3). Each is a pure `resolveX` plus a `describeX` that says on the boot line **which source answered** — `00 §5.7` bites hardest here, because every one of these is wrong in a way that looks exactly like being right.
- **Why a package: `18 §2` + `DEC-ARCH-001`.** All three had a second consumer, and `18 §2` makes *"Apps NEVER import ... other apps"* a MUST. `aging.ts` was `apps/pass-kds`'s and the counter reached across for it; the other two were `apps/pos-electron`'s and the pass reached across — which made the two apps a **cycle**. `DEC-ARCH-001` rules EXTRACT at the moment the second consumer appears, and rules against a copy for `03-F40`'s reason: a second local helper is a second interpretation, and the two diverge silently.
- **`03-F14` is ONE org policy and this is its only declaration.** `05-F1` alarms the manager off *"the red aging threshold (03-F14)"*, so a counter reading neutral while the pass reads red is three surfaces disagreeing about whether the food is late. Do not add a second threshold table anywhere, including a "just a default" literal in a component.
- **Two pinned readings live here, not in the FRs, and must not be re-decided silently.** (a) `03-F14` states defaults for dine-in and delivery only; **takeaway, pickup and an unknown/absent order type take dine-in's 10/20** (argued in `aging.ts`'s header). (b) A malformed threshold string is **REFUSED WHOLE and NOT APPLIED** — the shipped defaults stay in force and the reason is reported (`01-F17`, commandment 4: a typo must never take a surface down mid-service).
- **`packages → apps` is the inversion to watch.** Nothing here may import from `apps/` or `services/`; that compiles, links and runs while inverting `18 §2` outright (`DEC-ARCH-001` records the same trap). These modules take an env record, a raw string and a `run` callback as arguments precisely so they need no host.
- **No suite lives here, by design.** The behaviour is owned by the consumers' suites — `apps/pos-electron`'s `panel-density.test.ts`, `device-identity-seam.test.ts` and `orders-aging.test.ts`, and `apps/pass-kds`'s `pass-queue.test.ts`, `ready-mark.test.ts` and `__acceptance__/shared-config-extraction.test.ts`. The move duplicated none of them.
