# RestOS — Agent Guide

Restaurant OS for Pakistani restaurants. TypeScript monorepo (planned per `specs/18`), offline-first, event-sourced. **The specs are the contract: never code or edit from memory of a spec — open the owning doc first, per §2.** Full context rules: `specs/23-ai-context.md`.

**Map.** §1 commandments · §2 routing · §3 working rules · §4 the three standing laws · §5 running, measuring and proving (traps `T1`–`T12`) · §6 the lesson register `L1`–`L11`, cited elsewhere rather than retold · §7 scope (`plans/v0.md`), state and what is owed, dated.
⚠ **Read §5 before you run a command or quote a number** — `pnpm test` hangs forever in a sandboxed shell (`T1`) and a reported exit code is not evidence (`T2`). **Nothing here outranks a spec:** where this file and a spec disagree the spec wins, and then fix this file. Every number here is a dated measurement, not a fact (`L1`). ⚠ **Before you build anything real, read `plans/v0.md`** — v0 is FOUR items and everything else is v1 (§7).

## 1. Commandments (always binding; each is machine-enforced — violating code fails CI regardless of what you read)

1. **Append-only ledger.** Never mutate or delete history; corrections are new linked events (`01`).
2. **Never invent events, states, or policy.** Event types live in the `01 §4` catalog; order states in `01 §4` only. If the spec doesn't cover your case: STOP → check `specs/DECISIONS.md` → propose a spec change. Do not fill gaps with plausible behavior. **Any policy you assert must cite an FR ID that resolves** (`grep -arn "02-F9" specs/`) — an ID that greps to nothing means you invented it.
3. **Money = integer paisas; quantities = integer mg/ml/units.** Branded types from `domain`; floats in ledgers never (`00 §6`).
4. **Offline-first.** No in-branch feature may require WAN; confirmed = locally persisted before UI ack (`00 §5.1–5.2`). A sale is never blocked — not by inventory math, sync, or approval timeouts (`01-F17`, `05-F8`).
5. **Two-plane law.** Operational screens: `sync-client` reads/writes only. Cloud screens: tRPC + TanStack Query only. Never mixed silently (`18 §6`).
6. **UI = closed vocabulary.** `packages/ui` semantic components only; no raw primitives, no Tailwind arbitrary values in app code (`21 §2`).
7. **English-only UI; user content is Unicode** and renders/prints faithfully (`00 §5.6`).
8. **Server-side authorization always** via the `domain` permission matrix; client role claims are never trusted (`18 §5`).
9. **Spec change before behavior change.** Behavior-carrying code changes cite their FR ID (e.g. `02-F9`) in tests/commits; no matching FR = write the spec PR first (`20 §4.1`).
10. **Protected paths need an adversarial review in a SEPARATE agent context** — `domain`, `sync-client`, `sync-protocol`, `escpos`, tax, auth (`20 §4.4`). Hand the reviewer the FR IDs and the diff, never your reasoning: the frame that produced a blind spot is the frame that hides it. **There is no senior** (founder ruling, August 2026, retiring `20 §4.4`'s human-review leg); read `20 §4.4` on what is knowingly weaker about this than a human senior before treating a SHIP verdict as clearance. ⚠ `24-F20` and `.github/CODEOWNERS` still demand senior sign-off — spec PR owed (§7).

## 3. Working rules

- One module per session; load only the routed docs (a task needs ~2–4 specs, not the corpus).
- Build tasks follow the `24 §3` loop: approved plan → acceptance tests exist first (written by a **different** session; read-only to you) → implement → the named check passes → evidence (captured command output) in your final message. **"Done" is the check passing — never your own judgment.** The session that wrote a plan is disqualified as its own test author, and a brief's **⚠ Do NOT read** sections are load-bearing. Before writing any test here, read `plans/wave-1/oracle-round-2-findings.md` §C and `L10`; mutation is mandatory, and for a security parameter it happens out of tree (`T8`). Briefs and area plans are files, in `plans/wave-1/`. ⚠ **For v0's four gaps, R66 rules tests alongside the code in the SAME session** — a live conflict with `20 §4.3`'s separation rule, which is the FR and which R66 has not been carried into (§7).
- Craft rules (`24 §3b`): **surface assumptions in the plan** (ambiguous task → state interpretations, name the simpler alternative — don't silently pick); **minimum code that closes the FR** (no speculative features, flexibility, or error handling for implausible cases); **surgical diffs** (touch only the task's files; never "improve" adjacent code — cleanup is scheduled consolidation work, not a drive-by).
- Editing a spec: follow the template in `00 §8`; new FRs continue the doc's numbering; **never renumber or delete an existing ID** — supersede with a strikethrough plus a one-line pointer to the ruling that won, and let the reasoning live with the winner, never with the loser. ## 4. The three standing laws (ratified and shipped)

1. **The ordering design is per-fold merge semantics (`26`, `DEC-PERF-001`).** `01-F34`: folds declare explicit merge rules and read **no ordering metadata** — no `global_seq`, no `lamport_seq`, **no device clock**, no envelope-id comparison that reaches a projected VALUE. Tested by bijective id-relabel + clock-injection invariance; plain convergence testing is insufficient (a min-id tiebreak passes it while smuggling wall clock in through the UUIDv7 prefix). `global_seq` = delivery cursor + compaction watermark only. `causal_seq` remains refuted; `lamport_seq` keeps its gap-free transport/audit role. **This is the law most often broken by accident** — twice in the post-review round, each time by a projected value quietly depending on id sort order or on the reading device's state.
2. **Time is branch-consensus and stamped at APPEND (`01-F43..F46`, `DEC-TIME-001`).** Durations need a *consistent* clock, not a correct one. `branch_created_at` + `time_basis` travel INSIDE the event, because a fold applying its own offset would break law 1 silently. `device_created_at` is an untrusted forensic hint with exactly one sanctioned reader (`01-N2` skew detection). Branch time is continuous across hub re-election — the hub serves the clock, it does not define it. Business day = Asia/Karachi, 05:00 cutover (layer-2 configurable).
3. **Money is integers-in-a-double, and the double is the hazard.** Integer paisas only; rates as integer basis points; `splitPaisa`/`applyRateBps` for division and rates (`DEC-MONEY-005`). Folds accumulate in **BigInt** — float `+` is non-associative near 2^53, so a running double total lets delivery order decide a money outcome (a live law-1 break, not a theoretical range concern). A total that cannot be represented exactly contributes **zero** and raises `money_overflow`; never truncate, never throw on the ingest path (`01-F17`). The GritQL ban covers bare identifiers **and** money-named member expressions incl. `as` casts — comparisons and plain assignment stay legal on purpose.

## 5. Running it, measuring it, proving it

**Commands.** The runbook is `plans/wave-1/running-the-stack.md` — four processes and one Postgres from a clean checkout; the only document that gets you there, and it names what is still seeded and what is owed.
- Till: `pnpm rebuild:native` once, then `RESTOS_DEV_PIN=<digits> pnpm start` in `apps/pos-electron`. Device identity comes from `RESTOS_ORG_ID`/`RESTOS_BRANCH_ID`/`RESTOS_DEVICE_ID`, and the boot line names which were configured.
- Gateway: `pnpm -C services/sync-gateway start | migrate | provision-device --org … --branch … --device … --class … | revoke-device --org … --device …`. Docker is needed to TEST it, not to START it. A shell revoke emits **no event** (a shell has no authenticated actor), so it leaves no ledger record or attribution — the owner-facing path is `14-F13`'s device list. Un-revocation is not offered and the corpus is silent rather than permissive; `01-N5`'s replacement path is a fresh `device_id`.
- Print without a printer: `RESTOS_PRINT_TO_FILE=<dir> pnpm start` writes one PDF per document, one page per cut (`03-F42`). ⚠ **It is not evidence and must never become the default:** it renders what our own encoder thinks the bytes mean, paper never runs out in it (so `03-F41`'s hold is unreachable through it), and `27-F35`'s comprehension gate on real staff is untouched. With the variable unset the device ships `unattachedPrinter` and every confirm raises `03-F5`'s band — that band is the honest signal.

**The traps. Every one has already cost this project hours.**
- **`T1` — `pnpm test` HANGS FOREVER in a sandboxed shell.** vitest stays alive at 0% CPU inside `globalSetup` and zero containers are ever created, because the sandbox blocks the Docker socket. Not slowness, and no timeout saves you: run it unsandboxed, or run `pnpm -C services/sync-gateway test` separately. That suite needs local Docker (Testcontainers) and by design fails LOUDLY rather than skipping (`T-01-07`) — with Docker down, one missing turbo task and a red exit are an environment prerequisite, not a regression.
- **`T2` — a reported exit code is not evidence.** Not the harness's, not a background task's (backgrounded runs have been reported "completed (exit code 0)" while they were exit 1), and not `cmd > log; echo "exit=$?"` (the trailing echo succeeds after a SIGKILL). **Write `REAL_EXIT=$?` INSIDE the log and read it back**, or read the suite's own summary — turbo's `Tasks:` line.
- **`T3` — run `pnpm test --force --continue --concurrency=3`.** `--force`: a cached turbo run has produced a false green. `--continue`: turbo KILLS a failing task's siblings, so seven green suites are indistinguishable from seven killed ones. `--concurrency=3` is part of the measurement, not a preference: contended default-concurrency runs produce red sets that differ run to run and pass green in isolation — timeouts and dropped Postgres connections wearing assertion costumes, one of them a tab-COUNT assertion. Never report a parallel red as a regression without re-running that package alone, and never quote a contended run's total as clean.
- **`T4` — don't trust ONE green run, and a single RED run is exactly as untrustworthy.** Subprocess-spawning oracle suites flake on a 5 s default (`biome` via `spawnSync`, `tsc` via `execFileSync` — search the property, not the mechanism), and a killed suite leaves `.oracle-typecheck/` in the tree, which then reds `pnpm verify` on generated fixtures. `domain` once read 4-failed in a parallel run and 306/306 alone.
- **`T5` — use `grep -a`, always.** Under `LC_ALL=C` any UTF-8 byte (`—`, `·`, `₨`, `⚠`) makes a source file "binary", and grep prints `Binary file … matches` instead of its matching lines. Reproduced here: 7 matching lines without `-a`, 8 with, and the missing one was a real production call site. It never bites an interactive UTF-8 shell — only scripts, subagent shells and CI steps that inherit a C locale — and it answers more quietly rather than erroring. Treat `Binary file … matches` as a hit you have not read.
- **`T6` — read what `verify` runs off `package.json`, and what CI runs off `.github/workflows/ci.yml`. Never off this line: it has been wrong three times, in both directions (`L1`).** Measured 2026-08-23: `pnpm verify` = `docs:lint → typecheck → lint`; `pnpm verify:full` adds `tokens:check → strings:check → seams:check → layout:check`; **CI runs `docs:lint → typecheck → lint → test → build` AND `tokens:check`, `strings:check`, `seams:check`** — founder ruling R68 moved those three, because in `verify` they slowed every local run and gated no merge. ⚠ **`layout:check` is deliberately NOT in CI and is RED today — do not read that red as a regression.** `ci.yml` records the measurement (`0 fatal, 224 alarms, REAL_EXIT=1` under `xvfb-run`): 54 alarms are `probe-below-floor`, the row that EXISTS to fail, and 11 are the `27-F77` axis, red by design until the counter is rebuilt in v1. It goes into CI when it is green; a permanently red rail teaches everyone to ignore red.
- **`T7` — NEVER `git add -A` while agents are running.** One working tree is shared, so a blanket stage captures whatever everyone else has half-written: `8c03e4d` carries 132 lines of a concurrent session's protected-path file under a message that does not mention it. Stage explicit paths; if a stray path appears that your task did not touch, leave it — it belongs to someone still working. Corrections are new linked commits (commandment 1), never rewrites.
- **`T8` — mutation-test a SECURITY parameter out of tree only.** Agents get killed mid-task, and one killed between "weaken" and "revert" leaves live weakened crypto with every test green (`PIN_ARGON2ID_PARAMS` was flagged at `m=8,t=1,p=1` by a scan while an agent was proving the `01-F61` floor bites). Copy the package to a scratchpad and mutate the copy. In-tree mutate-and-revert stays fine for ordinary logic, where a stranded mutation reds a test instead of silently downgrading a credential.
- **`T9` — a new git worktree is cut from a STALE base, and a merged branch may not resolve.** First command in a worktree: `git log --oneline -1` against the target branch, fast-forward if behind (two cut in one session were 14 and 96 commits behind — far enough that the oracles the agents were sent to satisfy did not exist; `pnpm install --prefer-offline` is ~4 s). After merging a branch that adds a WORKSPACE DEPENDENCY, run `pnpm install` in the main repo, or one test FILE silently fails to load and the count reads low, with a `Cannot find module` that looks like a broken merge.
- **`T10` — `document.fonts.check()` returns `true` when no matching `@font-face` exists**, so it cannot be the font assertion. What bites: `load()` every weight (blocked bytes end at `status: "error"`), and measure the token family against a family that does not exist — equal widths mean the fallback. `system-ui` is out of the token stack because it resolves to **Roboto** on Android and ChromeOS, which `27-F26` bans; the bundled face is the only defence.
- **`T11` — happy-dom performs no layout**: every `getBoundingClientRect` is zeroes, so a `.dom.test.tsx` can express "the button is in the document" and never "the button is on the screen" (`L9`). And in `layout:check` output, a `withinViewport` failure means CLIPPED, not UNTOUCHABLE — conflating the two propagated from a verdict string into a `CLAUDE.md`, then into a task brief, and sent an agent to fix a blocker that did not exist.
- **`T12` — `BOOTSTRAP_ORG_ID` is a join key with three ends and no error message.** It must equal the till's device `org_id`, and `ENABLED_BRANCHES` must hold its `branch_id`, or all four processes report success and no till ever sees a menu. `apps/backoffice/CLAUDE.md`'s two-process example produces exactly that when copied into a four-process run.

## 6. The lesson register — cite `L<n>`, don't retell it

- **`L1` — every number and status claim in this file is a dated measurement, not a fact.** Re-derive it at the moment you quote it; when you write one, date it and say how you counted; prefer naming the command that prints it to transcribing its output. Instances: the suite total and the branch statement drifted apart twice (they move in one edit); the `seams:check` register was quoted at two different values inside this one document; the `verify` list was wrong twice (`T6`); and a measurement of a hardcoded device identity survived two later edits of this file although the code closed it **eight minutes** after it was written: a claim stated as a measurement reads as durable long past its shelf life.
- **`L2` — a derived document is not the source.** Waves come from `restaurant-os.md` Part I, and `00 §1`'s test is that a module's wave is when its first production slice ships to a dev-pilot — not when its package exists; `plans/` is not in the authority order at all, and a plan's task table is its ORIGINAL scope, never a status board. Reading `plans/wave-1/` as Wave 1's scope hid four Wave-1 modules that have no plan and a whole `restaurant-os.md` §8 item; the reconciliation is `plans/wave-1/wave-1-scope-reconciliation.md`. A stale task-ID table in `screen-map.md` once sent a session to build the **wrong screen**.
- **`L3` — when a ruling lands, grep the suites that encode the old rule the same day.** A GREEN test (`catalog-pricing.test.ts:394`) went on defending an overruled rule for about three weeks and would have failed the correct implementation: a test author flagged the hole, the founder ruled on it, and nobody carried the ruling back into the suite. Corollary: **a ruling governs code only where it has been carried into an FR.** The ruling register is `plans/saas-pivot/plan-of-record.md` §0 — read the ids off the file (65 rows on 2026-08-23, with `R66`/`R68` cited inside `R64` and given no row of their own); several are uncarried and the live FR still says the opposite — check both, and stop rather than pick. The tax cluster is this defect running right now (§7).
- **`L4` — a stale claim propagates fastest through the person fixing a different stale claim in the same paragraph.** It has happened twice here, inside the edit correcting the sentence beside it. The dangerous direction is UNDERSTATING: a security claim that understates enforcement invites the next session to "add" a check that already exists, or to route around one it believes absent.
- **`L5` — a proxy for the evidence is not the evidence.** A mention is not an import: strip comments and match the imported symbol, or say plainly that you counted mentions (a count of files reaching the permission matrix was inflated 9 → 2 by comment hits, and sent readers to a file with no gate in it). A barrel re-export is not a use (`seams:check` Rule A). A reported exit code is not the run's (`T2`). One mistake, three tools.
- **`L6` — search the property, not the symbol you expect.** A grep of `apps/pos-electron` for `device_token`/`persistToken`/`saveToken` found nothing and nearly re-filed a closed debt as owed: the shipped symbols are `persistRenewal`/`setDeviceToken`, one package over in `sync-client`, which is exactly where the FR puts them. Ask what the property would LOOK like before concluding from an absence.
- **`L7` — when you finish a subsystem, grep for its production caller before you call it done, and prefer that grep to the suite** — for this class of defect a passing suite proves nothing. **Mutate the SEAM, not the logic:** delete the call site and see whether anything reddens; if nothing does, the subsystem is decorative. You need both properties: removing a durable store from the shipped construction failed **1 of 160** tests (the seam assertion alone), while leaving it in place and making its `put` a no-op failed 4 — with the seam assertion still green.
- **`L8` — THE RECURRING DEFECT: a correct subsystem with no seam to the product.** Fifteen instances by 2026-08-15, all with every gate green, because tests exercise a module directly and nothing asserts the *application* reaches it. Worked examples: `createPinSession` had zero production callers while the shipped app compared `pin === "1234"`; the durable lockout engaged only if a host passed `store.pinAttempts`, and none did; the Argon2id cost floor was exported so a test could assert it, and none did; `audit.login`'s sink was wired in `sync-client` while the host passed `audit: () => {}`; K-6 mutation-proved a `Map`-backed spooler fails 8 durability tests, then K-7 wired the spooler and passed **no store**, so a power cut lost every queued kitchen ticket (`03-F4`). Later shapes: a service with no `dev`/`start` script, so a whole plane had never run as a process; an admission path that could RENEW a credential it had no way to ISSUE; a subsystem with no *configuration* by which the product could reach the state that uses it; `20 §4.2`'s Auditor, complete since Wave 0 and hosted by nothing. **The rail is `pnpm seams:check`.** Rule A — a value export no shipping code reaches (symbol-precise walk from `apps/*/src` + `services/*/src` minus tests/stories; a barrel re-export is not a use, the hole `createPinSession` fell through). Rule B — an *optional* member of an options bag on a factory shipping code already calls, that no call site ever passes; `knip --production` cannot express it. Exceptions are in-code markers carrying a reason, and a marker on something now reached FAILS, so the register cannot rot — read its counts off a clean run, never from here (`L1`). Both rails carry `24-F14`'s **empty-match protection**: a rule matching zero files FAILS, so a rename cannot silently disable a rail — asserted per scope half, because widening one walk once left the old tripwire inert behind a still-non-zero global count. **Three things it cannot catch, measured:** a constant exported so a test *could* assert it, and none did; **a port supplied with a STUB** (swap the real gateway publisher for the in-memory one: `verify` exit 0, `seams:check` clean, nearly every API test green, and no menu reaches any till — Rule B asks whether a member is supplied, never whether the supply is real); and a missing PRODUCER for an event type, because a key in an object literal is not an export. Each needs a hand-written assertion. **Closing one debt exposes the next** — Rule B had no candidate on `runAuditor` until a host existed, and the first clean run with one reported the FR's headline leg as unsupplied — so re-run `seams:check` expecting it to say something NEW.
- **`L9` — THE SECOND RECURRING DEFECT: a correct component that is not on the screen.** Nine layout defects by August 2026, every one found by launching the app and looking (or by the gate built from that habit), **zero** by the suites: `TAKE CASH` clipped so a cashier could not settle an order; `Counted Rs 0` entirely off-screen; `Approve`/`Cancel` below the viewport; a pager not subtracted from its own box — twice, in two components, slicing five menu tiles at 1024×600. **The rail is `pnpm layout:check`**: it opens a real `BrowserWindow` from the app's REAL window options (importing them — a gate measuring its own copy of the size proves only that its copy is right), mounts the shipped renderer, and measures in Blink against **every clipping ancestor between a control and the viewport** (a viewport-only walk reported 0 clipped controls while five tiles were visibly sliced). Composition requires content to FIT, per axis: a centred overflow of any magnitude scores asymmetry 0, so the check was passing the arrangement that hides its loss above the viewport and failing the one that puts it where a human looks. Playwright is the wrong tool — in a headless browser you *set* the viewport, so it is blind to the defect where the app does not get the size it asked for. **Its fixture is the real coverage boundary, not its assertions**: the alarm-band defects were invisible until the fixture raised a band. It judges nothing about legibility or contrast, `27-F4`'s positional contract is invisible to it, and it measures one DPI on one platform. It also carries one check that is **not** about fitting — `27-F8`'s keypad target measured in **millimetres of glass** (`27-F68`; `DEC-UI-001` ratified) — because a key that fits 1920×1080 perfectly can be 22.7 mm instead of 20. Below the panel floor the till CLAMPS and STARTS rather than refusing (`27-F11c`, `00 §5.7`); `PanelHealth` names the degradation. The panel roster, the floor's value and the `ships` rule live in `apps/pos-electron/CLAUDE.md` and `apps/pos-electron/src/layout-gate/main.ts`, and composition verdicts bind regardless of `ships`.
- **`L10` — reading a suite does not detect a vacuous test; only MUTATION does.** Five suites authored in parallel by five separately-warned agents were all returned BROKEN or WEAK for one defect in five costumes — the mechanism built correctly and never aimed at the case that matters: ~90 renders that never varied `data`; poisoned envelopes over a fixture the harness never ran; an oracle asserting against a hand-copy of the interface it existed to deliver, both symbols dead exports. **The standing requirement:** build a plausible implementation out of tree, take the suite green, then break the specific thing each assertion claims to own and confirm THAT assertion fails — and report the numbers, because a claim that a test bites is not evidence that it does. Use a **CONTROL** differing in exactly one branch, or your kill count proves nothing about attribution. A test that stays RED under a CORRECT implementation is as damaging as a vacuous one, because it blocks the implementer indefinitely; one round produced three. The wave's own defect has reproduced *inside* a fix for it — a seam test that mounted its own wiring and survived the mutant that mattered.
- **`L11` — a protection claimed in prose retires the assertion the next session would have written.** Three shipped comments have promised a protection that did not exist; one was **wrong when written**, in the change that made it true of the instance in front of its author: `01-F64` binds a device database to its identity, which closed "two different apps on one file" while "one identity, two processes" stayed open — a double-launched till then signed in, rang four items and showed `TOTAL Rs 0` against a locked database, with nothing on screen to distinguish it from a working till (closed by `01-F66`/`01-F67`'s single-instance lock). So when you write down what a fix now prevents, **state the class you actually closed and name the neighbouring case you did not.** ⚠ The comment at `packages/sync-client/src/device-store.ts:541` still says what it said — protected path, reported not corrected.
