# v0 — what one pilot restaurant needs to run a real service day

**Rule for this document: if a pilot can open tomorrow without it, it is not v0.**
Everything else is v1. This file is short on purpose and stays short.

## Already works (measured 2026-08-23, demonstrated end to end twice)

Owner authors a priced menu in the back office → publishes → a real Electron till
rings it at the price typed → sends to a durable kitchen spooler → settles by
method → closes the shift → owner reads the day. Staff identify, unlock against
Argon2id, and every write is authorized server-side.

Do not rebuild any of it. `plans/wave-1/running-the-stack.md` is how you start it.

## v0 gaps — the whole list

| # | Gap | Why it blocks a pilot |
|---|---|---|
| 1 | **Void / comp / discount have no producer.** Schemas and fold arms exist; the counter has no control. | A cashier mis-rings and cannot undo it. Under `01-F1` the error is permanent. No restaurant can trade like this. |
| 2 | **Tax is not on the bill.** `R54`/`R55` are ruled and spec-closed (`16-F27`..`16-F35`, `01-F82`); no code. | Pakistani restaurants charge tax. A bill without it is not a bill. |
| 3 | **Tax rates have nowhere to live.** `00 §7` layer 2. Carrier decided (`01-F87`); nothing built. | Rates differ per tender per org. For ONE pilot this may be seeded — decide when 2 is built, not before. |
| 4 | **K-8: no printer has ever been attached.** | Blocked on hardware, not on us. Everything else about printing ships. |

## Explicitly v1 — not v0, do not build yet

Billing · suspension enforcement · the signup door (provision a pilot with the
shipping CLI) · platform control-plane UI (seven CLIs already do it) · LAN mesh
and device pairing (one till per branch is fine for a pilot) · nightly summary
delivery (the owner opens the page) · manager console remote approvals ·
`order.cancelled`/`order.rejected` producers · storefront · foodpanda.

Each is real and each is recorded in `plans/saas-pivot/plan-of-record.md` §5.
None stops a restaurant trading.

## How v0 gets built (R66)

One agent per gap. Tests alongside the code, same session. Adversarial review
**only** where a defect is permanent and unfixable by a later release: money
arithmetic, the ledger, auth, the wire. Gap 1 and 2 both touch money, so both
get one review each — that is the only gate v0 keeps.

No new FRs unless a founder ruling demands one. The corpus has 896.
